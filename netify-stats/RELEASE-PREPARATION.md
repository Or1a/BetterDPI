## 规则扩充与未知流量分类

规则从 23,700 增至 23,895 条，标签从 1,407 增至 1,442 个。定向补入此前只存在于 DLC AI 类别文件中的 52 条服务域名，保持原生识别及已有规则优先。构建从固定提交重复运行，JSON 与两份许可证产物逐字节一致。新增协议分类、共享基础设施说明及全筛选范围的识别覆盖统计；schema 1/2/3 的字节数、连接数、分页和明细守恒回归通过，原始记录不因分类更新而改写。

为控制开销，不增加主动探测、DNS 查询、抓包、后台进程或数据表。协议判断只查固定名称表；证据最多五条，协议结果缓存最多 64 项，IP 校验只额外保留最后一个目标。覆盖统计复用应用汇总；LuCI 仍每 30 秒刷新一次。采集端仅在收到元数据时比较域名/协议质量，不在每个流量增量上重新运行分类规则。

采集对照为本轮规则扩充前的采集器；查询对照为同一 schema 3/分类器下，禁用新增协议维度与覆盖统计、使用旧规则的查询路径，计时包含规则加载。协议混合压力样本需要更细的分组，全网查询增加约 33 ms（36%），不能宣称所有查询都无额外开销。两种查询的总字节数一致；分类细分自然改变组数。规则 JSON 增加 7,915 字节（1.1%），`tracemalloc` 测得规则加载后的 Python 分配从约 5.709 MB 增至 5.754 MB，增加约 45 KB；这不是进程总 RSS 或路由器实测。

没有本次用户真实流量样本，因此没有实际识别率或 Unknown 下降百分比。只有 IP、协议也未知、或缺少内层信息的加密隧道仍保留未识别；协议或基础设施分类明确显示应用未识别，不计入已识别应用占比。

## 采集诊断与流量筛选

诊断面板直接使用已有采集器状态，不增加轮询端点或主动检查。它区分暂停、服务异常、状态过期和 Netify 连接状态，分别说明应用未识别与未归属设备的流量；没有新事件的空闲网络不会被标记为故障。状态时间与 RPC 返回的路由器时间比较，避免浏览器时钟不同导致误报。会话事件计数不相减推断丢失字节，配置损坏时先提示修复，不推荐点击已禁用的重试按钮。

识别层级、应用/域名搜索及应用聚焦共同作用于分页前的完整结果，总量、覆盖统计、时间趋势、设备排行和展开明细一致。域名搜索的规则证据只来自实际命中记录；内置应用名支持英文和简繁别名。设备搜索在已返回的名称、MAC、IP 列表中进行，不额外查询数据库。界面合并 350 ms 内的搜索输入，继续每 30 秒刷新，同一时刻只保留一个在途请求；过期响应不会覆盖较新的筛选。

普通查询不建立临时筛选表。筛选查询先按原有维度聚合分类，只把命中的组合写入连接内的 SQLite TEMP 主键表，256 项一批，页缓存 256 KiB；搜索名称缓存最多 1,024 项。RPC 使用文件临时存储，但路由器 `/tmp` 通常仍占 RAM，这不是整个查询的内存上限。字段类型与原表一致，使用索引判断命中；全命中时省略重复判断，无匹配时跳过事实表聚合。查询结束或异常后删除临时表，不新增持久统计表，也不修改采集增量路径。

迟到原生识别仍只影响后续增量。已有小时记录合并多个连接，回填前段字节必须增加逐连接贡献账本，并与代理纠正、容量清理及逐小时去重协调；本轮没有加入这部分采集核心改造。

## 手动更新与便捷下载

应用内更新仅在用户点击检查或确认安装时联网，没有定时检查、额外轮询或常驻更新进程。普通 summary 只读取有大小上限的本地更新状态；仅在任务运行中检查已记录进程的身份，不扫描进程列表，不执行包管理器命令，也不导入 HTTPS 网络栈。

更新清单固定取自 `Or1a/BetterDPI` 的最新稳定 Release，下载包绑定到已确认标签。仅接受 OpenWrt 24.10 的 IPK 或 25.12 的 APK，拒绝不匹配的系统、版本、文件名、大小和 SHA-256；HTTPS 采用系统 CA 验证，并限制重定向来源。清单上限 64 KiB、包上限 16 MiB，下载有总时限；安装过程不采用强制超时终止。用户不能通过 RPC 指定任意下载地址、包名或命令。

同一时刻只允许一项更新，任务在独立短期进程中运行。安装前后通过包管理器核对实际版本，不重装同版本、不降级、不执行全系统升级。APK 安装使用本地包及 `--no-network`，缺少新依赖时需要通过正常软件源补齐或手动升级。安装与分析开关串行；中断状态不会自动重试。设置与已有统计库沿用原有安装钩子及事务迁移，安装会短暂停止采集并重启 rpcd，不重启路由器，也不承诺升级窗口内统计连续。旧版没有更新入口，必须先手动安装一次包含更新器的 Release；安装失败不提供自动回滚。

安装子进程先在继承锁保护下记录自己的 PID 与启动时间，再执行包管理器；输出不依赖更新任务的管道。隔离故障注入验证了更新任务被杀后，假安装程序仍能完成，第二次更新和分析开关会被阻止，结束后显示中断而非伪报成功。新的手动操作会在取得锁、确认没有活跃安装后回收孤儿下载目录，普通查询不清理文件。本地状态读取七轮、每轮 10,000 次的单次中位耗时为：无状态文件 0.0033 ms、有可用版本状态 0.0111 ms；这是云环境微基准，不代表路由器总查询时间。

发布工作流从实际 SDK 产物生成 `update.json`，校验固定名称附件与带版本附件内容一致，六个附件一并校验。`INSTALL.md` 给出 opkg URL 安装与 APK 下载到本地后安装的步骤；APK 仅在单次本地安装中允许未签名包，不更改全局签名策略。发布清单测试和两种安装命令的隔离模拟检查均通过，错误校验和会阻止安装。实际构建与附件验证如下，旧路由器升级仍待实机测试。

1. **迟到代理映射去重。** 已针对原始 TCP 元数据先于 REDIRECT 映射、以及原始计数先于映射两种顺序做有界回溯修正，原复现脚本与新增回归通过。尚需在实际安装包中验证跨小时、过期及重启边界；候选缓存保留最多 60 秒或 4096 条，不承诺超出该窗口的迟到映射可纠正。
2. **许可证已确认。** 项目源码采用 GPL-3.0-only，允许商用；第三方规则逐来源保留 MIT 许可和来源信息。正式分发前仍需核对版权声明与依赖许可，不把许可确认误认为安装包已验证。
3. **SDK 与生命周期实测。** 使用官方校验过的 OpenWrt 24.10.8 x86/64 SDK 构建 IPK、25.12.5 x86/64 SDK 构建 APK；构建工作流已加入，产物和发布仍须以实际成功结果为准。干净安装、旧版升级、启用/关闭状态升级、卸载、重装、重启、sysupgrade、空间不足/配置损坏失败路径尚需验证。原生 APK 如单独生成，须明确注册安装/升级/卸载钩子，不能假定 install 脚本自动覆盖升级。
4. **长期采集与资源观察。** 无限制留存时空间会持续增加，这是用户选择，不得偷偷改成 7 天上限。测试小内存机、容量下调、长期读事务、连接突增和异常重连。
5. **可分发材料。** 最终审核 README、维护者/兼容性说明、源文件白名单、签名与校验和。不得把个人诊断文档、数据库、SSH 信息、流量样本和旧测试包整目录上传。
6. **手机实机确认。** 不使用浏览器自动化；保留命令行逻辑测试，与用户实机视觉反馈分别记账。

非阻塞精度边界：接口 A→B→A 若在同一约 3 秒采样周期内完成，A 可包含该周期内几秒流量；不同接口长期历史仍分离。接口 RX/TX 与应用层记录统计口径不同，不应通过把接口总量加到设备排行来“对齐”。
