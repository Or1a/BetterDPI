# BetterDPI Anti-PCDN 实验功能

日期：2026-11-01。本功能已合并主线并发布为 **V0.4.0 预发布试用版**；不是 V0.3.2 稳定包的一部分。两个官方 SDK 包已构建并核对，下载见 [V0.4.0 发布页](https://github.com/Or1a/BetterDPI/releases/tag/V0.4.0)，安装步骤见 [试用版说明](../INSTALL.md#v040-试用版)。外部项目和效果证据见 [项目调研](anti-pcdn-research.md)。

## 使用方式和边界

安装 V0.4.0 试用包后，在 LuCI「状态 → Anti-PCDN」打开独立页面。默认关闭，模式默认为「仅观察」。选择 Netify 实际采集的一个 LAN 接口，启用功能，保持 BetterDPI 采集运行。页面会列出短窗口内的连接、评分依据和不能自动处理的原因。

如需自动处置，切换到「自动封禁」并保存。默认阈值 **80 分（含）**，租约 **120 秒**；阈值允许 1–100，期限允许 30–600 秒。配置约 3 秒内生效，重启评分窗口；修改白名单或关闭功能也会清理旧租约。采集停止时本功能一起停止，不会偷偷重新开启用户暂停的统计服务。页面支持请求提前解除单个租约，并显示实际处理结果。

这是可解释的启发式评分，不是经过真实样本校准的 PCDN 概率。主动 BT、合法 P2P 分享也可能满足行为条件；请将需要保留的设备或明确域名加入放行列表。路由器无法仅凭网络行为推断用户是否授权分享。不能承诺零误判或彻底阻断所有 PCDN。

## 独立功能，共用输入

- `netify_features.py` 是采集器的可选订阅桥。仅在实时 socket JSON 解析后投递一次，不订阅第二个 socket，不新增抓包进程。
- `features/anti_pcdn/engine.py` 和 `scoring.py` 只处理短期连接状态；不读取或修改统计数据库、应用分类规则或历史汇总。
- `runtime.py` 用有界队列和独立工作线程处理评分、规则操作、状态和解除请求。防火墙命令不会阻塞采集线程。
- `conntrack.py` 和 `firewall.py` 负责执行前身份复核及内核短期规则。
- 配置、RPC、页面、菜单及 ACL 独立。配置为 `/etc/betterdpi-anti-pcdn.json`，运行摘要为 `/var/run/betterdpi-anti-pcdn/status.json`，均使用私有权限。配置可随 sysupgrade 保留，运行窗口和摘要不写长期历史库。

关闭时没有工作线程、窗口、事件拷贝或防火墙轮询；现有三秒维护周期只检查配置文件是否变化。评分线程异常与统计线程隔离。

## 当前评分

同一 LAN 接口、设备 MAC、本地 IP、传输协议和本地端口组成一组；动作仍针对具体连接。IPv4/IPv6 因本地地址不同自然分组。只接收选中 LAN 接口的 `internal=true` 事件，WAN 镜像不会进入评分。

| 证据 | 初始条件 | 默认分值 |
| --- | --- | --- |
| 对端数量 | 最近 60 秒至少 20 个有有效字节的公网对端 | 25 |
| 实质上传对端 | 最近 60 秒至少 8 个对端分别收到至少 64 KiB 上传 | 20 |
| 持续上传 | 最近 5 个完整分钟中至少 3 分钟上传达到 1 MiB | 20 |
| 上传占比 | 最近 60 秒上传至少 4 MiB，且达到下载的 3 倍 | 15 |
| 当前连接域名提示 | 同连接观测的主机名命中用户填写的 PCDN 域名提示 | 20 |

四类行为可以独立达到 80 分，无须域名才能触发。每项只贡献一次，按当前窗口重新计算，不能按上报次数累计刷分。可调整五项权重，每项 0–40，总和必须为 100。域名列表默认为空，不把第三方黑名单自动当作已验证用途；匹配精确主机名及带标签边界的子域名，不做关键词、共享 IP 或整个网段推断。

即便组达到阈值，每条被处置连接自身也必须在最近 60 秒有至少 64 KiB 上传、上传达到下载三倍，并保持新鲜活动。因此同组的纯下载或保活连接不会被顺带切断。STUN、QUIC、高端口本身不加分，也不是无条件豁免。

启动、重连或采集缺口后需要重新建立完整 300 秒观察覆盖。域名白名单、设备白名单、已识别 VPN、已知代理/共享传输、归属变化、窗口不完整及连接不再新鲜都会阻止自动动作。未知加密业务不会被武断地归为 VPN，也不会因此自动认定为 PCDN。

## 去重和数据质量

Netify 的 `local_bytes/other_bytes` 是增量，`total_bytes` 用作累计水位，`first_seen_at` 和 `last_seen_at` 用于身份及时间检查。元数据快照不计字节，历史导出恢复和统计重放不投递给评分器。

重复水位不再次计数；倒退、身份冲突、累计量不连续、超过 15 秒的迟到、跨度超过 60 秒的报告、队列丢失和容量不足会留下计数并使相关覆盖失效。时间窗按事件时间分配到十秒桶，边界桶宁可少计，也不将旧流量集中到当前时刻。单调时钟负责窗口和租约，墙上时间只用于事件年龄检查及显示。

封禁成功后移除该连接的评分样本，继续推进累计水位但丢弃租约期间的重试。到期后该连接必须获得新的完整观察窗口。相同元组换 digest 或出生标识也继承短期抑制状态；其他未封连接保留独立证据。被阻断的重试不能提高评分或自动续期。

## 自动执行范围

首版支持普通 **fw4/nftables、无卸载的 TCP/UDP 路由连接**，含 IPv4、IPv6、源 NAT 和无需目标地址转换的入站连接。每次动作前通过有时间及大小限制的 netlink 精确查询（至多两个方向），核对当前邻居 MAC、完整原始连接元组和内核 conntrack ID；至少两次新的观察确认同一内核 ID 后才安装规则。端口本身不作为身份。

已知流卸载、NSS/SFE 等厂商加速、TPROXY、未跟踪路径、非 fw4、目标重定向/DNAT、未知邻居或无稳定内核 ID 会拒绝新增封禁并显示原因。第一版不支持端口映射后的入站连接、纯二层桥接或不可分离的 VPN/代理外层。不会全局关闭加速、清空 conntrack、修改 fw4 规则或封整台设备。

规则仅存在于带所有权标记的 `inet betterdpi_anti_pcdn` 表。当前连接的 CT ID 经带内核超时的 verdict map 分发，再由接口、方向、地址族、协议及完整原始元组核对后双向丢弃。CT ID 碰撞或元组复用不会将不同连接当作同一目标。表名冲突时不接管其他人的规则。

正常关闭清理自有对象，强杀或崩溃后内核超时仍停止匹配；残留无效链在下一次启动/维护清理。安装失败会尝试回滚，无法确认清理时明确标为未验证。批次中断线或发生缺口时停止动作，刚安装的租约会尝试撤回。规则读回成功只能说明规则存在，不能声称已经阻断实际硬件路径或节省了多少流量。

限制为每轮最多尝试 4 条、每设备最多 16 条、总计最多 128 条当前租约。失败候选退避，不永久挡住后续候选；同一租约不因重复请求延长。限制优先保证开销和影响范围，处置是逐连接的，不能保证一次清除所有上传或阻止软件换端口。

## 资源预算与验证

队列上限 512 项，最多 2,048 个连接状态、512 组、每组 64 条连接、每设备 32 组及 16,384 个十秒样本。状态展示最多 50 个候选和 50 条动作记录，输出上限 256 KiB。容量耗尽会减少可判断范围并显示缺口，不分配无限内存。高并发环境可能长期达不到自动处置条件，应先看覆盖和丢弃计数。

评分约每 10 秒进行；配置及状态约每 3 秒更新。无逐 IP DNS/ASN 查询、主动探测、外部规则自动下载或长期端口明细库。样本上限是对象数量限制，不应误称整个 Python 进程的 RAM 上限。

仓库测试覆盖增量重放、WAN 镜像、缺失/延迟、下载共流保护、白名单、VPN、容量限制、窗口衰减、租约重试、连接身份、规则回滚、队列溢出、配置切换、独立 RPC/UI 和安装清单。隔离网络测试用于验证 nft 语法、匹配、TTL 与连接身份，不能替代 OpenWrt 真机验收。

下一步需用真实 PCDN 与合法 BT、备份、游戏、视频会议样本校准阈值，记录误处置、漏识别、CPU/RAM 和实际命中。当前实现不提供经过验证的识别率，也不将 WAN 差额称作拦截效果。

本次测试范围、性能测量及复现命令见 [验证记录](anti-pcdn-validation.md)。
