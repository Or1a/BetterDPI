# BetterDPI Anti-PCDN 设计草案

日期：2026-10-31。基于 `main` 的 `abe57d7` / V0.3.2，分支 `feature/anti-pcdn`。

状态：调研与设计；未实现检测器或下发防火墙规则。外部机制及效果证据见 [项目调研](anti-pcdn-research.md)。

## 目标和判断边界

目标是发现设备未经用户选择的 PCDN 上传分发，并在证据和路径明确时中止相关连接。正常视频下载、游戏、视频通话、云备份、主动 BT/P2P 同步、VPN 和远程访问应保留。不能把“上传多”“连接多”“用了 UDP/STUN/QUIC”“命中视频平台”单独等同于 PCDN。

检测和处置使用不同门槛：行为异常可以进入候选列表；自动封禁必须同时有明确的 PCDN 用途证据、上传行为证据、准确的连接归属和已经验证的执行路径。多个弱特征不能相加后自动变成强证据，分数只用于候选排序，不显示成经过校准的概率。

路由器不能从流量判断用户是否主动授权了某次 BT 分享，也不能仅凭端口恢复进程名。VPN、代理复用、HTTP/2 或 QUIC 内的不同业务可能共享一个传输连接；如果无法分离，本功能只能提示，不应把整个隧道当作 PCDN 切断。精确到五元组也不等于精确到业务流。

## 现有代码能复用什么、还缺什么

| 位置 | 可复用部分 | 为 Anti-PCDN 必须补充的部分 |
| --- | --- | --- |
| `netify_collector.py:normalize_metadata/update_metadata` | Netify 元数据、LAN MAC、协议、域名以及 TCP REDIRECT 归属 | 目前仅为 TCP 代理探测保存部分元组；需要统一保留 TCP/UDP、IPv4/IPv6 的完整元组、连接出生标识、接口/区域及域名证据来源。不能从已汇总域名反推当前 socket |
| `netify_collector.py:add_stats/reconcile_original` | 增量、方向修正、代理两段的选择及迟到纠正 | 现有逐小时连接数去重不是字节重放保护。供检测的新事件必须检查累计水位、重复和延迟，并能撤销迟到归属纠正影响，或在归属未稳定时禁止自动处置 |
| `netify_proxy.py` | 有界 conntrack 和 socket 快照；准确匹配时提供转发/本机进程线索 | 快照可能过期、截断或无法覆盖通配 UDP；代理进程名不能证明哪个终端应用，更不能把代理外层元组当作单设备封禁目标。执行前需要新鲜的、限定目标的复核 |
| `netify_wan.py` | WAN 增量去重、分层计量、缺失诊断 | WAN 是独立账，不能与 LAN 再算一次行为上传量；未知归属不能提升为全设备动作。按需复用去重实现，避免另起一套互相矛盾的口径 |
| `netify_storage.py/netify_query.py` | 小时统计、容量限制、七天明细和更早累计 | 当前明细已经聚合，没有完整端口/连接轨迹，不能回放成分钟级 PCDN 训练或处置数据。新增短期状态及少量事件摘要，而非扩大所有流量的历史粒度 |

## 识别：规则角色加短期行为

### 1. 规则明确用途和证据来源

规则条目需要 `id`、版本、来源提交、复核日期、匹配范围、用途和允许的动作。用途至少分为：

- **已验证的上传专用控制/数据服务**：只有确认与正常播放隔离，才可能给相关连接提供强用途证据。
- **PCDN 内容下载节点或共享服务**：只提示，不因为访问它就封禁。
- **关键词或未经复核的候选**：只用于排序和调查。

优先精确主机名和带标签边界的后缀匹配；默认不使用 `*pcdn*`、`*p2p*`、大网段或 AS 号封禁。SNI/HTTP Host 与 DNS 推断分别保留来源；DNS 返回过某 IP 不能证明该 IP 上所有连接属于此域名。缓存关联要包含设备和有效期，共享 IP 不能传播封禁。

同设备先访问一个调度域名、稍后出现大上传，也不足以把另一连接归到该调度服务。需要同流证据或经过验证的关联方式。Netify 显示 Bilibili、QUIC、STUN、BitTorrent 等泛应用/协议名不构成上传专属证据。

### 2. 短期窗口关注实际供数

按设备、接口/网络区域、地址族、协议和本地端口聚合，具体动作仍落到连接。观察不同活跃对端、具有实质上传的对端、上传量/持续性、上下行比例和端口变化。

仅有握手、保活、重复上报或下行 ACK 的端点，不应与持续供数端点等权。对端须有有效方向和字节依据；异常来自哪个连接，证据就保留到哪个连接。不要把全设备上传平均分摊给端口或进程。

用于离线校准的**起始实验参数**，不作为已验证的产品默认值：

| 特征 | 起始实验值 | 用途与限制 |
| --- | --- | --- |
| 单端口对端扩张 | 60 秒内至少 20 个不同公网对端 | 产生行为候选；IPv4/IPv6 分开看，地址数量不等于独立用户数量 |
| 实质供数 | 一个对端在窗口内上传至少 64 KiB，统计有此行为的对端数 | 降低握手/保活影响，仍无法单独排除合法 P2P |
| 持续上传 | 完整分钟内上传至少 1 MiB，最近 5 个完整分钟有 3 个满足 | 过滤短时突发；数据缺失的窗口标记无效，不能当作零流量 |
| 上传占比 | 上传大于下载 3 倍 | 辅助排序；视频会议、备份也可能满足，不能单独封禁 |
| 换端口延续 | 同设备在较长窗口内多个端口出现相似行为 | 仅产生设备级提示，不能将各端口弱证据汇总后封设备 |

允许按设备/设备组和用途调整观察窗口与告警敏感度；调整告警阈值不能绕开自动处置的强证据要求。设备历史基线可以提示“较平时异常”，不能把历史大流量自动变成正常白名单，也不能以首次出现为恶意依据。

### 3. 自动处置资格独立计算

保守自动模式须全部满足：

1. 用户已启用该模式，并将对应设备/业务纳入范围。
2. 有经复核的、能指向本连接上传分发用途的强证据，而非仅接触 PCDN 节点。
3. 当前连接有真实上传增量和持续活动；采集延迟、去重、方向及窗口覆盖检查通过。
4. 当前完整连接身份可确定，没有共享隧道、元组歧义、地址复用或未完成的代理归属纠正。
5. 没有适用的明确放行项或互相矛盾的业务证据。
6. 此路径的执行能力已验证，包括 IPv6、NAT、规则顺序和卸载情况。

只满足行为条件时显示“疑似 P2P 持续上传”，允许用户查看证据和临时处理，不直接定性为 PCDN。无法理解的加密流量保持“证据不足”。

## 处置：从当前具体连接开始

第一版执行器只支持已经验证的普通 LAN→WAN 路由连接。每次处置计划明确列出设备身份、当前地址、入口、协议、原始及回复元组、连接身份/出生时间、证据、作用方向、过期时间和实际可执行的后端。IPv4、IPv6 独立生成，不能用 IPv4 的证据自动扩大到全部 IPv6 流量。

默认是精确五元组/双向连接的短期阻断，不封整个视频平台、共享远端 IP、全部 UDP、本地端口的所有对端或整台设备。规则的下发可以是批量动态集合，不是一条流启动一个进程。

不能靠“只丢上传包”保证同连接下载正常：TCP ACK、QUIC 控制和复用流都可能受影响。需要同时说明该连接本身会中断；如果正常业务与 PCDN 共用同一连接且不可分辨，就不自动处理。

### nftables 生命周期

- 使用自有表/集合，少量固定匹配规则和有限个超时元素。第一版优先 fw4/nftables；不自动切到未验证的 iptables、bridge 或第三方代理规则。
- 能力检查、输入校验、目标新鲜度复核、批次校验、原子应用、读回确认依次执行。配置和元组是结构化数据，不开放任意 shell 命令。
- 确保普通路由路径中检查发生在 established/related 放行之前；仅调低 forward 优先级不能解决流卸载绕过。
- 元素有内核 TTL，起始试验可用 120 秒，并限制连续处置总时长。服务异常退出后规则仍会自行过期；正常停用立即清理自有动态条目。
- 续期必须取得新的有效用途/上传证据。LAN 侧仍看到被丢弃的重试、nft DROP 计数增加，不是继续运行 PCDN 的独立证据，不能据此无限续期。
- 流结束、设备地址改变、元组复用、规则撤回或用户放行时及时撤销对应条目。执行前复核 conntrack 身份；nft 元组不能匹配出生时间，因此仍需短 TTL 和关闭事件清理，并保留竞态测试。
- 不假定重复 `add element` 一定刷新 TTL；具体续期方式必须在支持的 nft 版本验证并读回。内核超时与单调时钟用于期限，墙上时间只用于展示。
- 防火墙重载、插件重启后先核对自身对象及当前连接，不将旧历史告警直接恢复成新封禁。不清空系统 ruleset 或全局 conntrack。

### 加速与代理能力必须单独验收

| 路径 | 第一阶段态度 | 后续达到什么条件才支持自动阻断 |
| --- | --- | --- |
| 普通路由、无卸载 | 可进入执行器验证 | IPv4/IPv6、NAT、双向及既有连接均有隔离网络测试和真实设备命中验证 |
| 软件 flowtable | 默认只观察，除非该拓扑的处置已验证 | 能只处理目标流的卸载/连接状态，或有先于 fastpath 且覆盖两方向的匹配路径；处理后还需防止目标立即重新卸载 |
| 硬件/NSS/SFE/厂商加速 | 不声称普通 nft 规则有效 | 目标加速后端支持可验证的精确撤销与命中观察；不以全局关闭加速作为默认补救 |
| TCP REDIRECT / TPROXY | 只观察已有可见内层证据 | 能在重定向前定位客户端原始连接，正确选钩子且通过 OpenClash/PassWall 实测；不能对共享代理外层连接下手 |
| WireGuard/Tailscale/OpenVPN 等不可见内层 | 显示隧道行为，自动处理不适用 | 有独立可归属的内层观察与执行点；不能由外层上传量猜内部 PCDN |
| 同 LAN 纯二层桥接或看不到真实设备的上游网关 | 不纳入首版自动执行 | 单独验证 bridge 路径及设备归属，不能混用普通三层 forward 方案 |

只有目标连接被确认时，才考虑定向 conntrack 删除；这不是默认补救。全表 flush、整机 UDP 禁用、全局 UPnP 关闭和全局加速关闭都不属于自动策略。

## 不重复采集、不虚报效果

复用现有 Netify socket，不新增抓包进程、不主动探测、不解密、不联网查询每个 IP。LAN、WAN、隧道计数继续分开；检测层对同一逻辑连接选择一个可信观察位置和规范方向，不能将代理两段或 LAN/WAN 两层相加。

每个分析增量带来源、连接身份、累计水位及覆盖状态。重复、倒退、过旧、无元数据或容量截断不能提升风险等级。迟到恢复事件不能让当前窗口看起来突然爆发，统计重放也不能重复触发动作。进程重启先清理旧分析状态并重新积累完整窗口，不能用部分观察马上自动封禁。

界面分别记录：

- **检测依据**：实际观测上传、对端数量、时间窗口、规则命中和不确定项。
- **执行状态**：计划、成功写入、已读回、已过期、失败、路径不支持；“已写入”不是“已止住”。
- **命中情况**：内核命中包数/字节，标明可能包含重试；反向或多点计数不得再次相加。
- **效果观察**：目标流是否继续、是否换端口/路径、正常业务反馈。WAN 前后差额不能命名为“节省流量”，没有命中也不能自动判为误报或成功。

默认排除本地管理、基础网络服务及用户明确放行范围。放行只使本插件跳过该目标，不覆盖系统防火墙自身策略；避免使用会意外绕开其他规则的全局 ACCEPT。

## 开销与存储预算

关闭时不分配观察窗口、不运行额外维护。启用后在元数据变化时分类，字节事件只做常数级状态更新；候选重评和防火墙变更批处理。不频繁扫描整个 conntrack 或查询 DNS，执行前的检查只针对有限候选。

首轮实现的上限草案如下，均需基准后调整，不能作为已测性能承诺：

| 状态 | 拟定上限与淘汰方式 |
| --- | --- |
| 活跃分析流 | 全局 4,096；还要限制每设备占用，防止单设备挤掉其他设备。去重状态被淘汰的身份须进入有界拒收保护或使受影响窗口失效，不能当作新流重新累加 |
| 设备端口候选 | 全局 512、每设备 32；优先保留有实质上传和明确证据的候选，容量到顶标记覆盖不足 |
| 对端关联 | 全局 8,192、每候选 64；达到上限只报告“至少 N 个”，不能伪装为精确总数；截断窗口不用于自动处置 |
| 观察窗口 | 60 秒和 5 分钟的小型环形桶，使用单调时钟；只保留活跃候选的短期状态 |
| 重评维护 | 每 10 秒分批执行，设置条数和协作时间上限；热点路径不执行 nft 子进程 |
| 动态处置 | 全局最多 256 个具体连接、每设备 16 个；不因容量不足改成封设备或网段 |
| 事件记录 | `/tmp` 中单独的有界事件摘要，建议先限 4 MiB；只保存状态变化、理由及少量端点样本，沿用容量回收，不保存载荷或全量逐流历史 |

测量必须同时包含 Python 对象、去重保护、临时表、日志、维护和执行器，不能只测一个匹配函数。验收记录同事件样本下的额外 RSS、CPU、延迟分布和容量截断次数，分别测试低端 ARM/MIPS 与 x86；未完成前不宣称“无性能影响”。不以扩大硬件开销换取少量未知流量的强行归类。

## 实施顺序和验收

1. **观察版**：补完整且可撤销的分析事件，加入规则角色、窗口和可解释候选；不接执行器。收集经用户确认的 PCDN 与正常业务样本，检查 IPv6、长连接、跨窗口及高并发。
2. **临时连接处置**：实现结构化处置计划、预览、有限期限、放行和撤销；在隔离网络中验证内核行为，再对实际路由器的普通转发路径验证。规则只命中预期连接，失败不扩大范围。
3. **保守自动模式**：只对已校准规则、充分覆盖的窗口及验证过的路径开放。无强用途证据的行为告警继续留给人工判断；软件/硬件加速、代理路径分别达到验收条件后再纳入。

最低测试矩阵：

| 场景 | 应有结果 |
| --- | --- |
| 从 PCDN 内容节点正常下载视频、yt-dlp 下载 | 不因域名或下载量自动封禁 |
| 云备份、大文件上传、主动 BT、P2P 同步、多人游戏、WebRTC | 缺少 PCDN 强用途证据时不得自动处置；明确放行始终有效 |
| 已验证的专用 PCDN 上传，多对端供数 | 展示用途与行为证据；仅对符合条件的当前连接生成处置计划 |
| 未知 TCP/UDP、STUN、QUIC、高位端口、单一大上传 | 最多异常提示，不直接认定 PCDN |
| VPN、代理复用、正常业务与 PCDN 共用元组 | 不封共享外层，不伪装成应用级控制 |
| LAN/WAN 镜像、REDIRECT 两段、重复 purge、迟到恢复 | 分析字节和动作不翻倍；归属变化可以撤销证据和旧计划 |
| IPv6 隐私地址、DHCP 换址、端口/元组复用、多 VLAN 同地址 | 不沿用另一连接或另一设备的封禁 |
| 缺失、重连、容量耗尽、时钟跳变 | 覆盖不足可见，暂停新增自动动作，旧租约正常过期 |
| 软件/硬件卸载、fw4 reload、进程强杀 | 不把写入成功当作阻断成功；自有租约能过期，不破坏其他防火墙策略 |
| 规则误判、撤回、禁用、升级中断 | 有明确撤销路径，允许项生效，旧历史不自动重放为封禁 |

准确率只基于有标签的样本报告，分别给出误处置连接数、误伤设备/业务数、漏识别量、触发延迟、处置后仍外发的目标流量和资源成本，保留分母与观察时长。合成回归用于验证机制，不能替代真实软件的前后对照。
