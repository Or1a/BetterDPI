# 设备分钟趋势（V0.4.1 试用）

V0.4.1 为设备流量增加短期分钟记录。趋势图默认显示最近 60 分钟，每分钟分别展示上传和下载两根柱子；选择设备后，图表使用该设备的分钟记录。

## 图表范围与统计范围

图表中的「图表时间范围」与页面上方原有时间选择独立：

| 图表选择 | 图中数据 | 总量和排行榜 |
| --- | --- | --- |
| 最近60分钟 | 最近 60 个分钟桶，包含当前未完成的分钟 | 仍使用上方选择的统计时间范围 |
| 所选时间范围 | 上方时间范围内的小时记录 | 使用相同的统计时间范围 |

页面会显示分钟图的实际起止时间。图表默认为最近 60 分钟，不意味着「全部」总量或排行榜也缩短为一小时。

应用聚焦、应用／域名搜索和识别层级筛选需要更细的分类维度，当前分钟表不保存这些维度。启用这些筛选时，图表回到所选统计时间范围的小时数据，并明确提示。设备选择可以直接作用于分钟图。

## 数据从哪里来

分钟记录复用已经计入设备账的 LAN 上传、下载增量，按采集器的实际记账分钟聚合。它是短期图表索引，不是第二次采集，也不会再加入原有小时总量。WAN 和隧道的独立账不会混入设备分钟图。

分钟粒度不等于逐包时间精度：Netify 上报延迟和统计纠正可能影响某分钟的数值。旧版只保存小时汇总，无法可靠恢复每分钟分布，所以升级前的小时记录不会被拆分或插值成分钟数据。升级后保持流量采集运行，新的分钟记录会逐步出现。

## 缺失与部分采集

采集器同时记录实际观察覆盖。暂停、断线、重启、缓冲丢弃或容量清理导致的缺口会显示为「未采集」或「部分采集」，不能把缺口解释为零流量。部分采集时已有的观察字节可以显示，但并不代表完整分钟的总量；当前分钟也可能尚未收集完整。

切换图表范围不会删除数据。暂停采集仍按原有设置保留已有记录，但暂停期间不会补造分钟数值。

## 保留与开销

| 项目 | 限制 |
| --- | --- |
| 时间保留 | 最多最近 120 个分钟桶，包含当前分钟 |
| 设备分钟记录 | 最多 32,768 行 |
| 写入缓冲 | 最多 2,048 个设备／分钟组合 |
| 存储位置 | 与原有统计共用 `/tmp/netify-stats/stats.db` |
| 提交 | 复用采集器约 3 秒的维护和提交周期 |

记录只保留分钟、设备编号和上传／下载数字，不扩展为端口、连接或域名明细。已有统计的容量清理可能提前删除相关分钟记录，行数或缓冲上限也会限制高并发时的覆盖；这些上限不是整个 Python 进程的 RAM 上限。功能不新增抓包、外部查询、独立采集线程或新的定时读取进程。

原有小时统计仍采用七天明细、更早累计的策略。分钟索引不会延长明细保留期，也不会改变历史总量口径。所有数据仍在 `/tmp`，路由器重启会清空。

开发主机配对测量使用同样的 32 台设备、20,000 个 UDP 增量和 SQLite 小时写入／提交周期，预热后测量 5 轮：原版本写入中位数约 129.18 ms，加入分钟索引后约 151.28 ms，增加约 22.09 ms，即每条事件约 1.10 µs。小时和分钟的上传／下载总数均与输入一致。这是写入路径的合成测量，不含 JSON 解析、socket 和状态文件开销，不代表路由器 CPU 占用或吞吐量。

## 升级提示

V0.4.0 用户需按 [V0.4.1 试用安装步骤](../INSTALL.md#v041-试用版)手动覆盖安装，应用内更新不提供预发布版本。安装后刷新 LuCI；如果浏览器缓存仍显示旧图表，请强制刷新。无需为了插件升级重启路由器。
